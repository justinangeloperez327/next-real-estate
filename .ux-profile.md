# UX Profile

Generated by `setup-ui-ux-skills`. All UI/UX skills in this project read this file before changing layout, copy, or interaction.

## Aesthetic reference

- **Standard:** Stripe
- **Notes:** Balanced density, calm whitespace, strong type hierarchy, subtle dividers and soft elevation only where needed. Restrained neutrals with one refined accent. Photography carries the public site; chrome stays quiet around it. Use tabular figures for prices, counts and dates. The current UI mixes ad-hoc colours (`bg-gray-800/900`, `bg-black`, `text-white`, `rose-600`) with shadcn tokens whose values contradict each other (near-black background, white cards). Move these onto one token set in `app/globals.css` before adding new surfaces. Fonts: Geist.

## Banned anti-aesthetics

- Gratuitous glassmorphism / `backdrop-filter` without a high-contrast boundary
- Floating pastel pill badges for ordinary metadata
- Arbitrary decorative gradients and neon glowing borders
- Multi-colour radial rainbow gradients on standard CTAs
- Cartoon empty-state illustrations (people waving / high-fiving)
- Nested scrollbars and icon bloat inside inputs

## Accessibility target

- **Level:** WCAG 2.1 AA
- **Contrast:** ≥ 4.5:1 for normal text; ≥ 3:1 for large text, UI borders and focus indicators. Text over listing photos and the hero video needs an overlay that keeps it at AA.
- **Touch / focus:** 44×44px minimum touch targets; visible, refined focus rings on every interactive element; respect `prefers-reduced-motion`.

## Brand tone and microcopy voice

- **Voice:** Warm & Humancentric
- **Capitalization:** Sentence case for UI copy and buttons
- **Notes:** Clear, empathetic and supportive. People are making a big decision about a home, so be reassuring without being chirpy. Use verb-first buttons ("Send message", "Save changes"). Errors never blame the user and always say what to do next.

## Icon library

- **Library:** Lucide
- **Package / path:** `lucide-react`
- **Notes:** Already the only icon set in use. Keep it that way: no second icon library and no emoji as UI icons. Icons that carry meaning need an accessible label; decorative ones get `aria-hidden`.

## Agent rules

1. Read this profile before creating or editing any UI, CSS, or microcopy.
2. Prefer skills by task: new page → `page-patterns` (name the pattern before markup); layout / chrome → `viewports`; forms → `forms`; overlays → `surfaces`; loaders → `loaders`; empty views → `empty-states`; motion → `motion`. Before finishing UI, run `ux-audit`.
3. Use only the recorded icon library (or project SVG path). Do not mix icon sets or use emoji as UI icons.
4. Never introduce items on the banned list.
5. Destructive actions always use an explicit confirmation dialog.
